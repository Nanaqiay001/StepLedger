# Feature：每日插画（pet 通道）

> 状态：**v4 MVP 已实现**（2026-11-06，Ark Seedream 实跑通过）。
> 本文只讲**用户看到什么、要满足什么**；技术落点、时序、改哪些文件见
> [桌宠通道架构](architecture-pet-channel.md)。
> 播报本身见 [桌宠播报](feature-pet-channel.md)；给模型的写法见
> [prompt 指南](prompt-pet-illustration.md)。

## 一句话

每天从判断结果里挑**一个瞬间**，让文本模型写成一段画面 prompt，再让图像模型画成一张
**3:4 的角色插画**（默认是蓝色鲸鱼娘）；桌宠播报时把这张图一起显示出来。

图里可以用**一个关键数字 + 一句短台词**点睛，但绝不能做成明细列表、表格或流水账——
它负责「有温度的一眼」，明细仍然在气泡和报告里。

## 为什么

现在每天能看的是「一段文字 + 一张余额折线」：

- 文字有温度，但读者要自己把数字在脑子里拼成画面；
- 折线能看趋势，但看不出「今天怎么样」；
- 桌宠已经有角色（`dsh-pet` 维护），但只会说话，没有图；
- 用户要的不是报表，是**一个具体、可感、每天不重样的瞬间**。

已经验证过的前提（2026-11-06）：

- dsh-pet 的 `/character?root=` 能给出角色三视图，作为生图参考图；
- 同一模型、同一 prompt 骨架，只多传一张参考图，角色一致性差距很大；
- 火山 Agent Plan 的 Seedream 5.0 flash 能出 2K、3:4、JPEG，角色一致。

所以这件事不是「再加一张图」，而是把**判断层的情绪**翻译成**一个画面**。

## 用户看到什么

某天超支，桌宠气泡里说：

> 今天多花的那一块钱，像鞋里进了粒沙——不碍走路，明天起床先抖一抖。

气泡旁边是一张 3:4 的插画：夜里书桌前，鲸鱼娘捏着一张小票，小票上只有一个手写的
「忍住」，眉毛垮下来，暖黄台灯、空钱包、一枚硬币。图和话是同一个瞬间，但图里的台词
只做点睛，不复读气泡。

再比如：

- 刚好卡在额度里：她合上电脑，长长呼一口气，夕阳照在发梢；
- 存下钱：抱着小猪存钱罐眯眼笑，金币落下；
- 没记账：空白账本上，笔尖悬着没落下；
- 里程碑：她把一枚小旗插在「进度条」的土堆上（慢变量镜头）。

## 范围

### 做

- 每天**最多一张** 3:4 竖版插画（原生 1200×1600，生成 2K；实测 1776×2368）；
- 角色来自 dsh-pet 的参考图，保持同一只、同一套服装；场景随当天事实变；
- 画面是**一个瞬间**，不是活动清单、不是总结海报；
- 数字和台词可以点睛（一个关键数 + 一句短句），但不能是明细 / 表格 / 图表；
- 失败就跳过：没有图，播报仍然只播文字；
- 默认不开启，配了生图 key 才用。

### 不做

| 不做 | 原因 |
|---|---|
| **不做角色素材库** | 角色和参考图由 `dsh-pet` 维护；StepLedger 不复制、不改角色设定 |
| **不做流水账 / 报表** | 数字和台词可以点睛，但明细列表、表格、图表、四格漫画一律不做 |
| **不做多图 / 视频 / 画廊** | 每天一张就够；多图是另一个 feature |
| **不在渲染渠道里调模型** | 渠道只投递；生图是内容生产，放在渠道之前单独一步 |
| **不每天重试到成功** | 失败就跳过，成本可控；不为了出图拖垮归档 |
| **不把图提交进仓库** | `archive/` 已 gitignore；角色图也不进公开仓库 |

## 怎么开

`.env`（gitignored）里配两行：

```bash
ILLUSTRATION_API_KEY=...                                   # 生图 key
ILLUSTRATION_MODEL=doubao-seedream-5.0-flash               # 默认值，可省
```

可选：

```bash
ILLUSTRATION_ENABLED=off          # 有 key 也想关掉
ILLUSTRATION_BASE_URL=...         # 默认 Agent Plan /api/plan/v3
ILLUSTRATION_REFERENCE=...        # 本地参考图兜底（旧版 dsh-pet 没有 /character 时）
ILLUSTRATION_CHARACTER=...        # 覆盖默认角色卡（视觉设定，不是 whisperPrompt）
PET_CHARACTER_ROOT=...            # 覆盖素材根
```

没配 `ILLUSTRATION_API_KEY` 时整段跳过：零网络、零新文件，播报回到纯文字。

## 每天留下什么

| 文件 | 内容 |
|---|---|
| `illustration.jpg` | 生成的图（JPEG/PNG，3:4） |
| `illustration_prompt.md` | 这次用的上下文 + 模型写出的 prompt（排查/复盘用） |
| `illustration.json` | 模型、尺寸、lens/moment、参考图来源、耗时 |

图和 prompt 都在当天的 `archive/YYYY-MM-DD/` 里；`archive/` 不进仓库。

## 失败会怎样

- 没 key / 判断降级 / 没有参考图 → **不画**，播报只播文字；
- 文本模型写不出合法 JSON → 重试 1 次，再失败跳过；
- 生图 API 失败 / 超时 → 跳过，日志里能看到原因；
- 图服务起不来 / 配图被拒 → 自动改播纯文字，退出码仍为 0；
- 任何情况下，`report.md`、`judgment.json`、`pet_task.md` 都照常产出。

## 成本

- 文本：1 次（写 prompt），约 5–7k tokens（指南较长；命中缓存会更低）；
- 图像：1 张 2K，约 16k tokens，10–30 秒（实测 29 秒）；
- 每天最多 1 张；失败不重试超过 1 次；
- 重跑渲染 / 全量重建默认不重新生图。

## 验收

1. **零配置零影响**：没配 `ILLUSTRATION_API_KEY` 时，产物与现状一致、零网络、
   没有 `illustration.*`；现有测试全过。
2. **真能出图**：配好 key + 可用的参考图后正常跑一天，
   产出 `illustration.jpg`、`illustration_prompt.md`、`illustration.json`；
   图是 3:4、2K（实测 1776×2368）；图内最多一个关键数字 + 一句短台词，
   没有明细列表/表格/图表。
3. **角色一致**：连续 3 天用同一张参考图；人工看三张，发型/耳鳍/围裙/尾巴不跑偏；
   `illustration.json.reference` 都是 `character`（或配置的 `local`）。
4. **不重复**：连续 3 天的 `lens` / `moment` 不完全相同；最近 3 天的画面真的被参考。
5. **失败不拖垮**：把图像 API 打成 500 / 超时，`report.md`、`judgment.json`、
   `pet_task.md` 照常产出；日志里有原因；`pet_play.py` 仍能只播文字。
6. **带图播报可读回**：`pet_play.py --image` 后，宠物读回状态里的图片地址
   等于脚本起的临时地址；图被取走后服务关闭。
7. **隐私**：仓库零 key；prompt 里没有账户尾号/商户名/明细列表；金额只用一个关键数；
   参考图与生成图都不进仓库。
8. **可单独补图**：补图不会重写 `report.md`；重跑渲染不会调用图像 API。

## 未决问题（产品）

1. **谁来写 prompt：管线里的文本模型，还是宿主 agent？** 现在是管线调一次文本模型
   （复用判断层的配置；cron 也能出图、口味可版本化）；缺点是每天多一次文本调用。
   让 agent 写更省一次调用，但没有 agent 时就没图。先按管线做，等实际口味跑一轮再定。
2. **agent 要不要能改 prompt/moment？** 特殊日子（生日、破纪录）可以手工改画面；
   这是第二个入口，先不做。
3. **图要不要也给 console/IM？** 图是共享产物；先只给 pet，等 IM 回来再复用。
4. **参考图不可用时，出不出「通用角色」？** 现在的答案是**不出**——宁可不画，也不画错人。
5. **prompt 指南放 `docs/` 还是打进包？** 现在放在 `docs/`；
   如果 skill 发布时不带 `docs/`，要挪到包内并写进包数据。
6. **旧版 dsh-pet（0.4.4/0.4.5）怎么办？** 要么升级到含 `/character` 的版本，
   要么配一张本地参考图；两条都写进安装说明。
