# 次日清点（settle）：把昨天定格

> 对应 issue #15。状态：已落地。

## 一句话

当天跑完的账一定可能不完整——素材是持续追加的；所以第二天先回头把昨天清一遍，再算今天。

## 为什么必须做，而且必须排在今天之前

管线每天只跑一次，跑完就把当天写进归档。但短信是持续追加的，于是：

| 数字 | 口径 | 漏记影响 |
|---|---|---|
| 月度累计 | 月初基线 − 当前余额 | 下一次运行就追平 |
| 近 7 天 | 余额序列逐日相减 | 基本会追平 |
| **某一天花了多少** | 那天归档的余额快照 | **永久停在旧值** |

日粒度是唯一不自愈的数字，而它正好是「今天额度超没超」的输入：

```
今天花了 = 昨天的余额 − 今天的余额
```

昨天 20:30 那笔如果没进昨天的快照，它会被算到**今天**头上——错的不只是昨天，还有今天。
所以清点必须发生在今天的判断之前：

```
collect(今天) → settle(昨天) → judge(今天) → render(今天)
```

清点失败不阻塞今天：捕获、写日志、继续。

只在 `run_date` 就是今天时自动清点。用 `--date` 补跑历史日时不动它的前一天——那是显式的
历史重放，不该被自动修正悄悄改变。

## 判据：素材指纹

`runtime.materials_digest` 记录「这次判断消费了哪一版素材」：

```
sha1( 文件名 + 字节 + 文件名 + 字节 … )   # material_files 已排序，与顺序无关
```

每次 `_judge` 结束时写入。次日清点时：

1. 先按日期再拉一次源素材（`FolderAdapter` 本来就是「同名覆盖最新快照」）
2. 比对指纹
   - 相同 → `unchanged`：**0 次模型调用、一个字节都不重写**
   - 不同 → 往下走

## 两种路径

| 素材状态 | 做法 | 理由 |
|---|---|---|
| 还在 | 整份重判（观察 → 事实 → 趋势 → 说话） | 事实与话必须同源（决策 D1） |
| 已清理、当天没有事实 | `secretary.backfill`：只补事实 | 旧归档升级；不能拿模板话覆盖原文（D5） |
| 已清理、当天已有事实 | 什么都不做 | 没有今天的余额，重算只会把好数字改坏 |

第三行是这次特地加的：`backfill` 用空观测算事实，会丢掉落款日自己的余额；
对一个已经有事实的日子重跑它，等于用「不知道」覆盖「知道」。

## 不播报是类型约束，不是 if

`BaseChannel.broadcast`：`console=False`、`pet=True`。清点调用
`_render(..., only_record=True)`，跳过所有 `broadcast` 渠道。

于是清点会更新 `report.md` / `milestones.md` / `trend.svg`（记录要自洽），
但不会写 `pet_task.md`、不会让宿主 agent 把昨天当成新闻播出去。

## 失败不写盘

清点复用 `_judge`，而模型不可用时它会把判断降级成 stub。若拿降级结果覆盖，
就是 D5 事故重演：好文本被模板话替换。

规则：**新判断 degraded 而旧判断不是 → 不写盘、不更新指纹、返回 `failed`。**
下次运行会再试，天然自愈。

## 与 `--rebuild` 的关系

| | `settle` | `--rebuild` |
|---|---|---|
| 范围 | 最近 N 天（默认 1 天） | 全部归档日 |
| 触发 | 每天自动，或 `--settle` | 手动 |
| 成本 | 素材没变就是 0 | 每天一次模型调用 |
| 语义 | 定点修正 | 全量重放 |

`--rebuild` 太重，不该每天跑；清点是每天最多一次的定点修正。

## 三个开放问题，我们的答案

**1. 重判后旧文本要不要留档？**
就地覆盖，在 `runtime.settled` 留痕：

```json
"settled": {"at": "2026-11-06T10:06:24", "from": "<旧指纹>", "to": "<新指纹>", "rewrote_prose": true}
```

理由：`judgment.json` 是历史的唯一载体，`History` 只认它；再开一个 `judgment.v1.json`
就要教所有读取方忽略它。旧文本是「数据不全时的临时读数」，留痕比留文更有用。

**2. 跨零点算哪一天？**
保持**文件名日期**。那是银行自己给这笔账的归属，接口层不该替它改口径。
在文件里写 23:59、却被记到第二天，是源数据的性质，不是我们的 bug。

**3. 连续多天漏跑怎么办？**
`PIPELINE_LOOKBACK_DAYS`（默认 1，0 = 关闭）控制清点几天，**从旧到新**逐日处理：
先清 D-2 再清 D-1，后一天读到的就是刚清过的前一天。
连续漏跑的语义（整窗重判 vs 逐日）仍然是逐日——顺序正确就不会互相污染。

## 验收对照

| issue 的验收 | 用例 |
|---|---|
| 源文件被追加 → 次日 facts 与最终状态一致 | `test_appended_material_is_rejudged` |
| 源文件没变 → 不调模型、不重写 | `test_unchanged_spends_no_tokens_and_writes_nothing` |
| 素材被清理 → 只补事实、原文不动 | `test_cleaned_materials_only_backfill_legacy_facts` |
| 清点不播报 | `test_settlement_never_broadcasts` |
| 清点失败不影响当天 | `test_settle_failure_does_not_block_today` |
| 昨天那笔不能算到今天 | `test_daily_run_settles_yesterday_before_today` |

## 不在范围

- 实时账单流水（另一个量级）
- 改定时时间：19:00 该跑还是跑，清点是补偿
- 改「当天」的判定逻辑（仍以文件名日期为准）
