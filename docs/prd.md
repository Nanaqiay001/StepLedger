# StepLedger — 产品需求文档（PRD）

## 一句话

每天通过收支记录采集，由 AI 每日解读收支是否偏离目标，让你每天离小目标近一点，最后攒成 100 万编年史。

## 是什么

StepLedger（跬步账）是一个**全自动理财日记系统**。它每天把各方的收支素材收拢成文件，由 AI 做一次定性判断——最近的钱花得怎么样、下一步可以怎么调——再渲染成一眼能看懂的东西，自动归档成财务编年史。

## 产品哲学

- **定性优先，不求定量** — 不做精确对账、不做预算超支判定、不追求数字严谨。要的是"最近花钱是什么感觉"，不是一张损益表。
- **有温度** — 像朋友提醒一句，不是财务审计。允许模糊、允许主观，但必须具体、可感知，让人愿意明天再看一眼。
- **仅供参考** — 判断层的建议是启发，不是指令。用户永远有最终决定权。
- **跬步千里** — 不追求一夜暴富，每天看一眼、调一步，积少成多。
- **零人工干预** — 装在你自己的 agent 上之后，由 agent 每天定时跑一遍，你只需要看；没有常驻 agent 的机器，才退回系统 cron 兜底。

## 目标用户

有存钱/理财小目标的个人用户，愿意让 AI 每天帮自己看一眼收支是否在正轨上。

## 核心需求

### 主功能：每日理财日记

- **采集层** — 从各方收拢素材（账单、截图、随手记、转发消息），只落成文件，不做任何解读
- **判断层** — 读素材，产出「最近花销总结 + 理财建议」，重温度不重严谨，仅供参考
- **渲染层** — 把判断结果可视化（终端卡片 / 图片 / 网页）并归档
- 逐日自动完成：**定时由宿主 agent 负责**（例如它每天 21:00 的日常任务），采集 → 判断 → 渲染一次跑完；没有常驻 agent 时用 cron 兜底

### 辅助功能

- 手动触发单次运行（调试/补跑）
- 手动补投素材
- 历史编年史查阅

### 素材来源

- **MVP**: 手动输入 / 消息转发 / 快捷指令自动写入的素材夹（如 iCloud，`COLLECT_SOURCE_DIRS`）
- **Future**: 支付宝、微信支付、银行账单自动拉取、图片 OCR

## 成功标准

1. 管线跑通：一份素材 → 判断（Stub AI）→ 渲染 → 控制台输出，端到端可运行
2. 每日一跑零人工：宿主 agent 定时触发（或 cron 兜底）→ 自动完成 → 素材、判断、产物按日期归档
3. 判断有温度：用户读完能说出"最近钱花得怎么样"和"明天想怎么调"，且不觉得是在被审计

## 附录：Alternatives Considered & Why

记录走过的弯路和被否决的方案，供后人理解为何是现在这个设计。

| 方案 | 结论 | 原因 |
|------|------|------|
| TypeScript 全栈 | ❌ 否决 | 项目是装在 agent 上的 Python skill，TS 过重 |
| 纯前端 SPA | ❌ 否决 | 需要常驻 agent / cron 定时执行，纯前端做不到 |
| 严格定量账本 | ❌ 否决 | 精确对账成本高、体验冷，用户坚持不下来；改为定性判断 |
